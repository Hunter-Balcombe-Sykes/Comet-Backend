## P3 — Nice to have

- [ ] **#XREPO-1** · P3 — Vestigial public-booking BFF proxy for a subsystem the backend never shipped
    - **Where:** Frontend `app/api/public/booking/availability/route.ts`, `app/api/public/booking/checkout/route.ts`, `app/api/public/booking/config/route.ts`, `app/api/public/booking/services/route.ts`, `app/api/public/booking/_shared.ts`
    - **Affects:** No live users. Verified there is no live caller anywhere in the frontend repo (repo-wide grep for `api/public/booking` returns only the route files themselves and one stale line in an unrelated full-repo file-inventory checklist) and no matching backend route exists.
    - **Effort:** S (~0.5–1h)
    - **What to do:**
        - Delete the four BFF route files **and** `app/api/public/booking/_shared.ts` (the proxy helper only these four routes import — DeepSeek's draft missed this file).
        - Delete the parent `app/api/public/booking/` directory once empty.
        - No other frontend reference exists to update — confirmed by repo-wide grep.
    - **Technical:** The backend's full 387-route surface contains zero `api/public/booking/*` routes — only `PATCH api/booking/settings` (the authenticated dashboard endpoint) and the `api/platforms/booking/*` smart-detect category routes exist. `config/partna.php`'s `features.smart_booking` flag (`'smart_booking' => (bool) env('PARTNA_SMART_BOOKING_ENABLED', env('SIDEST_SMART_BOOKING_ENABLED', false)),`) defaults `false`, and its docblock confirms it "gates all /booking/* routes (professional, public, analytics)". A repo-wide grep of the frontend for `api/public/booking` turns up no call site outside the proxy files themselves — no page or component invokes them. Note the proxy already degrades gracefully rather than surfacing a raw 404: `_shared.ts`'s `proxyUpstreamGet`/`proxyUpstreamPost` fall through every unreachable target to a friendly `{"message": "Booking service is unavailable right now. Please try again."}` 502 — so even a hypothetical stray caller would not see a broken contract, just dead, silently-inert code.
    - **Plain English:** These are five files that exist only to forward requests to a "smart booking" feature the backend team never built and that's currently switched off. Nothing in the website actually calls them today — they're leftover wiring for a feature that stalled before launch. Deleting them is pure tidy-up: nobody loses anything, and it's one less thing a future developer has to puzzle over.
    - **Evidence:**
        ```php

        'smart_booking' => (bool) env('PARTNA_SMART_BOOKING_ENABLED', env('SIDEST_SMART_BOOKING_ENABLED', false)),
        ```
