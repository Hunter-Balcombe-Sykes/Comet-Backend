    - **Where:** partna-frontend-main/app/(app)/account/(dashboard)/integrations/products-section.tsx:18-19
    - **Affects:** Developers maintaining `products-section.tsx` — no runtime or user-facing impact (bundlers tree-shake unused imports out of the production build).
    - **Effort:** S (~0.5h)
    - **What to do:**
        - Remove `Card, CardDescription, CardFooter, CardHeader, CardTitle` from the `@/components/ui/card` import.
        - Remove the `CardGrid` import from `@/components/ui/card-grid`.
        - Grep the file for `<Card` first to confirm nothing was missed, then run the frontend lint/build.
    - **Technical:** `ProductsSection` imports six components from the card family (`Card`, `CardDescription`, `CardFooter`, `CardHeader`, `CardTitle`, `CardGrid`) but its JSX return only renders `StoresTable`, `StoreSettingsSection`, `DangerCard`, `ProductsTable`, `AddProductModal`, and `ConfirmAlert` — none of the six imported card primitives appear anywhere else in the file (verified against the live file on disk, not just the pasted excerpt: the only other match for the substring "Card" is the unrelated `DangerCard` import/usage). This is residue from an earlier layout that has since been replaced by `StoresTable`/`ProductsTable` (spec references F3.3/F3.7 in the file's own comments), left behind because this repo's ESLint config apparently doesn't enforce `no-unused-vars` on this import shape.
    - **Plain English:** The file pulls in six page-layout building blocks it no longer uses anywhere — like keeping ingredients in your kitchen for a recipe you stopped cooking. It doesn't break anything or slow anything down, but it clutters the file and makes a future reader wonder why they're there. Deleting the two import lines is a five-minute cleanup.
    - **Evidence:**
        ```tsx
        import { Card, CardDescription, CardFooter, CardHeader, CardTitle } from "@/components/ui/card"
        import { CardGrid } from "@/components/ui/card-grid"
        ```
