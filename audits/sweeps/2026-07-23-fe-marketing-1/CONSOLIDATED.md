## P3 — Nice to have

- [ ] **#XDEAD-1** · P3 — Dead frontend public-booking BFF subsystem (4 routes + shared helper) proxies to a backend contract that was never built
    - **Where:** `$PARTNA_FRONTEND_PATH/app/api/public/booking/{availability,checkout,config,services}/route.ts`, `_shared.ts`
    - **Affects:** Nobody today — zero callers anywhere in the frontend repo. Bundle bloat and a future-maintainer trap only.
    - **Effort:** S (~0.5–1h)
    - **What to do:**
        - Delete the whole `app/api/public/booking/` directory (4 route files + `_shared.ts`).
        - No backend change needed — the backend never registered `/public/booking/{availability,checkout,config,services}-by-slug` under any route file.
        - If native in-site booking checkout is ever rebuilt post-pilot, treat it as a fresh design against whatever backend contract exists then — this code isn't a usable starting point, since no backend counterpart was ever shipped for it to talk to.
    - **Technical:** Each of the four BFF routes proxies through `_shared.ts`'s `buildBookingUpstreamTargets()` / `proxyUpstreamGet` / `proxyUpstreamPost` to `/public/booking/{availability,checkout,config,services}-by-slug` on the backend. A repo-wide grep for `api/public/booking` across the frontend returns only these five files themselves plus one stale planning doc (`docs/superpowers/plans/2026-07-22-file-audit-checklist.md`) — no page, component, or hook ever fetches these paths. The backend's `routes/api/platforms.php` does define a `/platforms/{provider}/booking/*` group (`BookingController::detect/detectStatus/status/forget`) and `routes/api/user.php` defines `/booking/settings` (`UserSiteController::updateBookingSettings`), but those are the authenticated dashboard's manual-mode booking-link and smart-link-detection features — structurally different from a public per-slug availability/checkout API. No `/public/booking/*` prefix exists anywhere in `routes/`. This is inert dead code from the 2026-05-22 commerce/marketplace strip-down (per `project_standalone_strip_down`), not a live regression.
    - **Plain English:** Four hidden mail-drops were built into the site's plumbing to handle booking appointments directly through a professional's page, but that in-site booking-and-checkout feature was removed from the backend months ago and its mail-drops were never taken down. Nothing is broken today — no button or page anywhere sends mail to them. They're just leftover scaffolding that could mislead a future developer into thinking in-site booking still works; tidying them up now is cheap and prevents that confusion later.
    - **Evidence:**

- [ ] **#XDEAD-2** · P3 — Dead frontend waitlist BFF route — the live `/waitlist` page no longer calls it
    - **Where:** `$PARTNA_FRONTEND_PATH/app/api/public/waitlist/route.ts`
    - **Affects:** Nobody — the live `/waitlist` marketing page already switched onto a different, working endpoint. Bundle bloat only.
    - **Effort:** S (~0.5h)
    - **What to do:**
        - Delete `app/api/public/waitlist/route.ts`.
        - No page changes needed — `app/(marketing)/waitlist/page.tsx` already renders `<EarlyAccessForm>`, which posts to `/api/public/early-access`, a live route matched in the backend contract inventory.
        - Leave `config('partna.waitlist.enabled')` alone — it's an unrelated signup kill-switch flag read by `PreAccountBuildController` / `PublicSignupAvailabilityController`, not connected to this route.
    - **Technical:** This file proxies `POST /api/public/waitlist` to `${apiBaseUrl}/public/waitlist` on the backend. No such route exists in `routes/api.php` (a repo-wide grep for `waitlist` under `routes/` returns zero matches), and its target controller was retired: `supabase/migrations/20260719000000_drop_waitlist_signups.sql` drops the `core.waitlist_signups` table, and `config/partna.php`'s `waitlist.enabled` key carries the comment "Signup kill-switch, NOT a waitlist capture path (retired 2026-07-19)" — confirming the backend controller this file proxied to no longer exists. Crucially, this is not a live 404: `app/(marketing)/waitlist/page.tsx` renders `<EarlyAccessForm variant="full" size="lg" autoFocus />`, and `early-access-form.tsx` posts to `EARLY_ACCESS_ENDPOINT = "/api/public/early-access"`, which maps to `POST /public/early-access` — present in `routes/api.php` (`Route::post('/public/early-access', [PublicEarlyAccessController::class, 'store'])`) and in the MATCHED bucket of the contract inventory. A repo-wide grep for `/api/public/waitlist` confirms zero live callers — only the dead route file itself and a stray comment in `early-access/route.ts` ("same proxy mechanism as /api/public/waitlist") referencing it historically.
