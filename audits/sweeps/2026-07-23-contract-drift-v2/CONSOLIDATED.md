## P3 — Nice to have

- [ ] **#XDEAD-1** · P3 — Dead frontend public-booking BFF subsystem (4 routes + shared helper) proxies to backend paths that were never built
    - **Where:** `$PARTNA_FRONTEND_PATH/app/api/public/booking/{availability,checkout,config,services}/route.ts`, `_shared.ts`
    - **Affects:** Nobody today — verified zero callers anywhere in the frontend repo. Bundle bloat + a future-maintainer trap only.
    - **Effort:** S (~0.5–1h)
    - **What to do:**
        - Delete the whole `app/api/public/booking/` directory (4 route files + `_shared.ts`).
        - No backend change needed — confirmed the backend never registered `/public/booking/{availability,checkout,config,services}-by-slug` under any route file (`routes/api.php`, `routes/api/publicSite.php`, `routes/api/platforms.php`).
        - If native in-site booking checkout is ever rebuilt post-pilot, treat it as a fresh design against whatever backend contract exists then — this code isn't a usable starting point (no backend counterpart was ever shipped for it to talk to).
    - **Technical:** Each of the four BFF routes proxies through `_shared.ts`'s `buildBookingUpstreamTargets()`/`proxyUpstreamGet`/`proxyUpstreamPost` to `/public/booking/{availability,checkout,config,services}-by-slug` on the backend. A repo-wide grep for `api/public/booking` across the frontend returns only these five files themselves plus one stale planning doc — no page, component, or hook ever calls them. The backend's `routes/api/platforms.php` does define a `/platforms/booking/*` group (`BookingController::detect/detectStatus/status/forget`), but that's the authenticated dashboard's smart-link-detection integration, a structurally different feature from a public per-slug availability/checkout API — the two were never the same contract. This is inert dead code, not a live regression: DeepSeek's draft (#XREPO-2/#XDEAD-1) correctly identified the absence of a backend counterpart but split it across two lens prefixes with inconsistent framing (one calling it a "candidate 502," the other calling it dead code); adjudication confirms dead code is the accurate description and merges the duplicate.
    - **Plain English:** Four hidden mail-drops were built into the site's plumbing to handle booking appointments directly through a professional's page, but that in-site booking-and-checkout feature was removed from the backend months ago and its mail-drops were never taken down. Nothing is broken today — no button or page anywhere sends mail to them. They're just leftover scaffolding that could mislead a future developer into thinking in-site booking still works; tidying them up now is cheap and prevents that confusion later.

- [ ] **#XDEAD-2** · P3 — Dead frontend waitlist BFF route — the live `/waitlist` page no longer calls it
    - **Where:** `$PARTNA_FRONTEND_PATH/app/api/public/waitlist/route.ts`
    - **Affects:** Nobody — the live `/waitlist` marketing page was already switched onto a different, working endpoint. Bundle bloat only.
    - **Effort:** S (~0.5h)
    - **What to do:**
        - Delete `app/api/public/waitlist/route.ts`.
        - No page changes needed — `app/(marketing)/waitlist/page.tsx` already renders `<EarlyAccessForm>`, which posts to `/api/public/early-access` (a live, matched backend route).
        - Leave `config('partna.waitlist.enabled')` alone — it's an unrelated signup kill-switch flag read by `PreAccountBuildController`/`PublicSignupAvailabilityController`, not connected to this route.
    - **Technical:** DeepSeek's draft (#XREPO-1) asserted this is a live 404 because the `/waitlist` page "routes still include /waitlist," inferring the page must submit to this endpoint — it does not verify the page's actual implementation. Reading `app/(marketing)/waitlist/page.tsx` shows it renders `<EarlyAccessForm variant="full" size="lg" autoFocus />`, and `early-access-form.tsx` posts to `EARLY_ACCESS_ENDPOINT = "/api/public/early-access"`, which maps to `POST /public/early-access` — present in `routes/api.php` and in the CONTRACT-INVENTORY's MATCHED list. The dead route's own backend target (`PublicWaitlistController` writing to `core.waitlist_signups`) was retired 2026-07-19: `supabase/migrations/20260719000000_drop_waitlist_signups.sql` drops the table, and `config/partna.php`'s `waitlist.enabled` key carries the comment "Signup kill-switch, NOT a waitlist capture path (retired 2026-07-19)" — confirming the backend controller this file proxies to no longer exists. A repo-wide grep for `/api/public/waitlist` confirms zero live callers (only the route file itself and a comment in `early-access/route.ts` referencing it historically). This is dead code with no live-user impact, not the P1 live-404 DeepSeek proposed — re-tiered down and reclassified from XREPO to XDEAD accordingly.
