    - **Affects:** Developers maintaining the Apple Music / Apple Podcasts / Bandcamp integration pages. No end-user impact — the branch never executes in production.
    - **Effort:** S (~0.5–1h)
    - **What to do:**
        - Reconfirm no caller passes `view="all"` (already verified repo-wide: every exported wrapper — `MusicSection`/`MusicAccountsSection`/`MusicReleasesSection`, the Podcast and Bandcamp equivalents — passes `"overview"`, `"accounts"`, or `"releases"`; none omit `view` or pass `"all"`).

        - Delete the `view === "all"` branches this forces throughout the component (`accountsSelectable`, the items-table `headerRight` Select button, and the accounts/items visibility gates).
        - Delete the stale header comment describing `"all"` as a still-supported backward-compatibility mode.
    - **Technical:** The file's own header comment states plainly that `"all"` is "the original single-page layout kept for backward compatibility — no current caller passes it." This is independently corroborated: a repo-wide grep for `view="all"` and for every `AppleConnection` consumer turns up nothing that reaches this component with that value, and `docs/superpowers/plans/2026-07-21-dashboard-rebuild-plan.md` already lists "delete dead `view=\"all\"` branch + stale comments" as an outstanding, not-yet-executed cleanup item — confirming this is known, tracked debt still present in the current source. The dead branch isn't inert: `accountsSelectable`, the Select-button `headerRight`, and the accounts/items visibility gates all fork on `view === "all"`, so every future edit to this ~250-line component has to reason about a fourth state that can never actually occur.
    - **Plain English:** This file has a leftover "show everything on one page" mode from an earlier version of the Music/Podcasts/Bandcamp screens, plus several if-checks scattered through the file that only exist to support that old mode. Nothing in the app asks for that mode anymore — the code's own comment admits it, and a separate planning document confirms the team already flagged it for removal. It's harmless today, but it's dead weight that makes the file riskier to safely change, like a light switch still wired to a room that was knocked down.
