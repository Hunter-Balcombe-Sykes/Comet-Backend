- [ ] **#TEST-1** · P2 — `SectorTaxonomy`'s ordered-keyword classifier is only pinned against two collisions
    - **Where:** tests/Unit/Profile/SectorTaxonomyClassificationTest.php:9-20
    - **Affects:** `IdentitySync`'s Google/Instagram category folding — any future reorder of `KEYWORD_SECTORS` (~50 entries) that isn't specific-before-generic silently misclassifies a business's sector, which then drives the wrong `ProfileDesignPresets` auto-styling.
    - **Effort:** M (~2–4h)
    - **What to do:**
        - Add a data-provider test iterating every `KEYWORD_SECTORS` entry, asserting each representative input still resolves to its intended slug.
        - Add explicit collision-pair tests beyond barber/bar — e.g. `car repair` / `car wash` / `car dealer` all pointing at different slugs, `event venue` / `event planner`, `dance school` / `dance`.
    - **Technical:** `SectorTaxonomy::classify()` returns the first substring match from an ordered `array<string,string>` — correctness depends entirely on keyword ordering (the class's own docblock calls out "specific-before-generic ordering discipline"). The only pin (`tests/Unit/Profile/SectorTaxonomyClassificationTest.php`) covers `barber`/`bar` plus one null-path case; `tests/Unit/Profile/SectorTaxonomyTest.php` adds a couple of Instagram-parity checks but no additional ordering pins. None of the other ~15 documented collision-sensitive pairs in `KEYWORD_SECTORS` (car repair/wash/dealer, event venue/planner, hotel, dance school/dance, restaurant vs cafe/bakery/bar tail-matches) have a regression test, so a future edit reordering the map for an unrelated reason has no safety net.
    - **Plain English:** The system guesses a professional's industry from text like "Barber shop" by checking a list of keywords in a specific order — checking for "barber" before the more generic "bar" so a barbershop doesn't get miscategorized as a bar. Only one of these order-sensitive pairs is actually tested; roughly fifteen others (car repair vs car wash, event venue vs event planner, etc.) could get silently broken by a future edit and nobody would notice until a business's website styling looks wrong.
    - **Evidence:**
        ```php
        it('classifies "Barber shop" as barber, not bar', function () {
            expect(SectorTaxonomy::fromGoogleCategory('Barber shop'))->toBe('barber')
                ->and(SectorTaxonomy::fromInstagramCategory('Barber Shop'))->toBe('barber');
        });
        it('still classifies a plain "Cocktail bar" as bar', function () {
            expect(SectorTaxonomy::fromGoogleCategory('Cocktail bar'))->toBe('bar');
        });
        ```
