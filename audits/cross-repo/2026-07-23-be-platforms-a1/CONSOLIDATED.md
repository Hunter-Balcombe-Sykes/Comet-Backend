## P3 — Nice to have

- [ ] **#SLOP-1** · P3 — Decorative banner comment separator in `AppleSearch.php`
    - **Where:** app/Services/Platforms/AppleSearch.php:104
    - **Affects:** Maintainers reading the file — zero runtime impact.
    - **Effort:** S (~0.5–1h)
    - **What to do:**
        - Delete line 104 (the `// ── internals ──...` line). The blank line already separating the public API from the private helpers below is sufficient visual grouping.
    - **Technical:** Violates the explicit CLAUDE.md Code Conventions rule: "Comment for WHY, not what... No paragraphs, restatements, banners." Method visibility (`private`) already signals `itunes`, `hdArtwork`, `resolveArtistId`, and `resolvePodcastId` are internals; the banner adds a decorative line that carries no information the signatures don't already convey.
    - **Plain English:** It's like putting a decorative divider page in a binder between the public chapters and the private chapters — the table of contents already tells you what's what, and the divider just adds bulk. Removing it keeps the file leaner without losing any information.
    - **Evidence:**
        ```php
            // ── internals ────────────────────────────────────────────────

            private function itunes(string $path): ?array
        ```

- [ ] **#SLOP-2** · P3 — Decorative banner comment separator in `EventsCatalog.php`
    - **Where:** app/Services/Platforms/EventsCatalog.php:364
    - **Affects:** Maintainers reading the file — zero runtime impact.
    - **Effort:** S (~0.5–1h)
    - **What to do:**

    - **Technical:** Same CLAUDE.md violation as SLOP-1 ("No paragraphs, restatements, banners"). The grouped methods (`adapter`, `rowsFor`, `accountRows`, `eventRows`, `dropElapsed`, `sortEvents`, `fail`) are already `private` and sit after the public storage methods; the banner is unnecessary visual noise on top of structure the code already expresses.

- [ ] **#SLOP-3** · P3 — Unused optional `$size` parameter on `hdArtwork()` — every caller takes the default
    - **Where:** app/Services/Platforms/AppleSearch.php:133
    - **Affects:** Maintainers — the parameter signals flexibility that doesn't exist.
    - **Effort:** S (~0.5–1h)
    - **What to do:**
        - Remove the `$size` parameter; hardcode `600` in the `str_replace` call.
    - **Technical:** CLAUDE.md's "Do NOT over-engineer" ("three similar lines > a premature abstraction") applies to parameterising for flexibility no caller uses. Verified via grep: `hdArtwork()` has exactly two call sites in this file (lines 38 and 68, both `$this->hdArtwork($url)` with a single argument — no third call site, contra the draft's "lines 31, 56, 63") and zero external callers (it's `private`). The `int $size = 600` default is never overridden anywhere.
    - **Plain English:** It's like having an extra button on a remote control labelled "volume" that's permanently glued to level 10 — nobody ever changes it, but every new person reading the manual has to learn what it does. Just hardwire the volume and remove the button.
    - **Evidence:**
        ```php
        private function hdArtwork(?string $url100, int $size = 600): ?string
        {
            return $url100 ? str_replace('100x100bb.jpg', "{$size}x{$size}bb.jpg", $url100) : null;
        }
        ```

- [ ] **#SLOP-4** · P3 — Duplicate `ACTOR` constant defining the same Apify actor name in two sibling scrapers
    - **Where:** app/Services/Platforms/GoogleBusinessApifyScraper.php:28 and app/Services/Platforms/GoogleMenuImagesScraper.php:24
    - **Affects:** Future maintainers — if the actor name changes (e.g. Apify migrates the actor ID), one file may be updated and the other silently drifts, breaking the image-scan path.
    - **Effort:** S (~0.5–1h)
    - **What to do:**
        - Add a `'actors' => ['google_places' => 'compass~crawler-google-places']` entry under the existing `'apify'` key in `config/services.php` (which already holds `apify.token`).
        - Replace both `private const ACTOR = 'compass~crawler-google-places';` declarations with `config('services.apify.actors.google_places')`.
    - **Technical:** Category 6 copy-paste duplication, confirmed verbatim in both files (and nowhere else in `app/`) via repo-wide grep for the literal. Both classes already read `config('services.apify.token')` from the same `services.apify` block, so adding one sibling key is the lowest-friction single source of truth — no new config file, no new service class. Note: an older, unrelated archived finding (`audits/archive/2026-07-08-full-sweep/audit-2026-07-08-lifecycle-correctness.md`) flagged this same constant for being an *unpinned* actor build (a version-pinning concern) — that is a separate, already-triaged issue and not a duplicate of this DRY finding.
    - **Plain English:** Two rooms in the same house each have their own handwritten copy of the Wi-Fi password taped to the wall. If the password changes, someone updates one room and forgets the other — now half the house has no internet. Put the password in one place they both read from.
    - **Evidence:**
        ```php
        // GoogleBusinessApifyScraper.php:28
        private const ACTOR = 'compass~crawler-google-places';
        ```
        ```php
        // GoogleMenuImagesScraper.php:24
        private const ACTOR = 'compass~crawler-google-places';
        ```
