### FE-DRIFT-2 · P2 · Charlie font-change tool schema advertises 8 font slugs the handler rejects
**Source run:** `fe-lib-1`. **Confined to the frontend chat-engine layer — no backend route/contract involved.**
**Where:** `lib/chat-engine/registry.ts:433` (`design_set_font` tool description) vs `lib/chat-engine/action-design-handlers.ts:34-42` (`FONT_SLUGS` allowlist).
**Impact:** Any Charlie AI Copilot user asking to change their sitepage font by name — 8 of the 9 advertised slugs (`origin, melodrama, parceh, humane, reglo, oswald, ostrich-sans, young-serif`) are **rejected** by the handler; only `geist` works. The handler's own error hint names two *more* invalid slugs (`oswald, young-serif`), so a retry loop can fail twice.

**What to do:**
- Update the `design_set_font` description in `registry.ts` to the real 7-font roster: `geist, inter, general-sans, monument-grotesk, forma-djr, helvetica-neue, helvetica-now`.
- Fix the fallback error message in `action-design-handlers.ts` (it suggests invalid `oswald`/`young-serif`).
- Ideally derive the tool description from `FONT_SLUGS` (or the shared `FONT_OPTIONS` in `use-individual-typography.ts`) so the two can't drift again.

**Effort:** S (~0.5–1h). **Evidence:**
```ts
// registry.ts:433 — advertises stale slugs:
description: "Set the sitepage font by slug. Valid slugs: geist, origin, melodrama, parceh, humane, reglo, oswald, ostrich-sans, young-serif.",
```
```ts
// action-design-handlers.ts:34-42 — handler only allows 7:
const FONT_SLUGS: ReadonlySet<string> = new Set(["geist","inter","general-sans","monument-grotesk","forma-djr","helvetica-neue","helvetica-now"])
```
