## P3 — Nice to have

- [ ] **#SLOP-1** · P3 — Unused `User` import in UserLinkBlockController
    - **Where:** app/Http/Controllers/Api/User/SiteManagement/UserLinkBlockController.php:15
    - **Affects:** Developer reading the file — a stray import implies the class is used somewhere in the file when it is not; no runtime impact.
    - **Effort:** S (~0.5–1h)
    - **What to do:**
        - Delete line 15 (`use App\Models\Core\User\User;`).
    - **Technical:** No method in the file type-hints, instantiates, or statically references `App\Models\Core\User\User` — every occurrence of the token "User" in the file is part of a different identifier (`ResolveCurrentUser`, `currentUser()`, `authorizeForUser()`, `*LinkBlockRequest`). Confirmed via `Grep 'User\b'` against the full file body: the only literal match on the class itself is the import line. This project has no root `pint.json` overriding the default preset, and the default Laravel Pint preset does not enable `no_unused_imports`, which is why this survived the 06-11 Pint-baseline cleanup. Category 3 (dead code — unused import).
    - **Plain English:** This line tells PHP "I'm going to use the User blueprint in this file," but the file never actually uses it. It's a leftover from an earlier version of the code. Deleting it changes nothing about how the app behaves — it's just tidying up.
    - **Evidence:**
        ```php
        use App\Models\Core\User\User;
        ```

- [ ] **#SLOP-2** · P3 — Redundant `method_exists($customer, 'trashed')` guards in UserCustomerController
    - **Where:** app/Http/Controllers/Api/User/Customers/UserCustomerController.php:122, 134, 169
    - **Affects:** Developer reading the file — the guard implies `trashed()` might not exist on `Customer`, which is never true, and the pattern is applied inconsistently within the same file.
    - **Effort:** S (~0.5–1h)
    - **What to do:**
        - Line 122: change to `if (! $includeArchived && $customer->trashed()) {`.
        - Line 134: change to `if ($customer->trashed()) {`.
        - Line 169: change to `if ($customer->trashed()) {`.
    - **Technical:** `Customer extends BaseModel` and declares `use HasUuids, SoftDeletes;` (Customer.php:33) — `trashed()` is unconditionally defined on every instance. The `method_exists` check guards against a scenario the class declaration rules out. The pattern is applied inconsistently even within this one controller: `destroy()` (line ~155) calls `$customer->trashed()` directly with no guard, and the parallel `UserServiceCategoryController` (same domain, same soft-delete pattern) never uses the guard at any of its four `trashed()` call sites (lines 88, 100, 115, 170). Category 4 (redundant defensive cruft — null/method check on a value the type system already guarantees).
    - **Plain English:** This is like checking whether a car has a steering wheel before turning it — every car in this fleet has one, guaranteed, because of how the `Customer` class is built. The check was probably written defensively at some point and never cleaned up, and it isn't even applied consistently — one method in the same file skips it entirely. Removing it makes the code shorter with no change in behavior.
    - **Evidence:**
        ```php
        // line 122
        if (! $includeArchived && method_exists($customer, 'trashed') && $customer->trashed()) {
        // line 134
        if (method_exists($customer, 'trashed') && $customer->trashed()) {
        // line 169
        if (method_exists($customer, 'trashed') && $customer->trashed()) {
        // destroy() — no guard, proving the guarantee:
        if (! $customer->trashed()) {
        ```
