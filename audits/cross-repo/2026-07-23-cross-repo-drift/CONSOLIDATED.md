## P2 — Should fix

### FE-DRIFT-1 · P2 · Orphaned public-sitepage BFF + query surface (booking + waitlist + public query factory)
**Owner:** frontend (pure deletion). **Source runs (converged):** `contract-drift-v2`, `capability-wiring-v2`, `dead-subsystems-v2`, `fe-marketing-1`, `fe-dash-staff`, `fe-dash-b`, `fe-dash-c`, `fe-components`, `fe-lib-2` — the single most-confirmed finding in the campaign, plus a direct reconciliation grep (below).
**Root cause:** leftover scaffolding from before the public sitepage renderer moved to the separate `@partnaau/design-system`/Astro app, never swept in the 2026-05-22 standalone strip-down or the 2026-07-19 waitlist→early-access rename. Three dead layers, one origin.

**Files to delete (all frontend, zero live callers):**
- `app/api/public/booking/{availability,checkout,config,services}/route.ts` + `app/api/public/booking/_shared.ts` — proxy to `/public/booking/*-by-slug`, routes that **never existed** on the backend (grep of full `routes/` tree confirms).
- `app/api/public/waitlist/route.ts` — proxies to `/public/waitlist`; its target `PublicWaitlistController` + `core.waitlist_signups` were retired 2026-07-19.
- `lib/queries/public.ts` + `lib/queries/fetchers/public.ts` — the whole 7-member "Public sitepage rendering query factory" (`profile`, `siteBySlug`, `bookingConfig`, `bookingServices`, `joinByHandle`, `configIntegrations`, `configSocialPlatforms`).
- Trim the matching cases from `lib/queries/public.test.ts` (currently the **only** caller of any of the 7 factory members).

**Reconciliation (why the whole query factory, not just booking):** `fe-lib-1` scanned `lib/queries` directly and *missed* this (a recall miss); `fe-components` caught it via whole-repo grep. Settled by a direct grep on `main @ 5234954`:
```

# imports of lib/queries/public or lib/queries/fetchers/public: NONE (except the test)
# fetchPublicProfile / SiteBySlug / JoinByHandle / ConfigIntegrations / ConfigSocialPlatforms
#   are referenced ONLY inside lib/queries/public.ts itself (factory wiring).
```
→ The entire factory is dead. Confirmed.

**⚠ Do NOT touch (verified live — deleting these would be a regression):**
- `app/(app)/account/(dashboard)/booking/*` and `BookingDashboardSection` — **live** provider-connect feature calling real `platforms/{base}/booking|fresha|square` routes (graduated out of Integrations 2026-07-18, capability-gated).

**Note:** `configIntegrations` targets `/public/config/integrations`, which the backend **deliberately moved behind auth** (routes/api.php SEC-1) — the frontend simply shouldn't call it pre-auth; no backend action needed.

## Negative results (verified — no action, but load-bearing)

These are the "no action" conclusions that make this report otherwise empty. They are why the boundary is called healthy.

- **Capability / availability wiring is in sync.** `capability-wiring-v2` (scope: `app/Services/Accounts`, `config/partna.php` vs frontend `lib/account-capabilities.ts`, `lib/account`, `lib/integrations`) surfaced **no drift**. No `integration.*` / `feature.*` rule is exposed on one side of the boundary and consumed on the other in a mismatched way.

- **No cross-repo-provable dead backend route surfaced.** The deterministic inventory (`../CONTRACT-INVENTORY.md`) put **380 backend routes** in the UNRESOLVED bucket (no *static* frontend caller). The XREPO adjudicator promoted **none** of them to BACKEND-ONLY dead — correctly: the frontend reaches the backend through a **BFF layer + a typed dynamic API client**, so a literal-string grep can't see most call sites, and "no static caller" ≠ "dead". A definitive dead-backend-route verdict requires tracing the frontend's dynamic client, which this campaign did not exhaustively do.
  - The backend's large `api/platforms/*` surface (shop/shopify/square/booking/reservations/online-ordering/opentable/…) is a **candidate** area for a future dead-route pass — many platform types were stripped from the frontend in the 2026-05-22 standalone strip-down — but proving any of those routes dead needs the dynamic-client trace above, not a cross-repo diff. **Not asserted here.**

- **The "missing" backend endpoints are deliberately gone, not gaps to fill.** The frontend BFF proxies that dead-end (`/public/booking/*-by-slug`, `/public/waitlist`) point at endpoints that were **never built** (booking checkout) or **intentionally retired** (`PublicWaitlistController` + `core.waitlist_signups`, dropped 2026-07-19 → replaced by the live `POST /public/early-access`). **Do not add these routes** — the fix is the frontend deleting the stale proxies (FE-DRIFT-1).

- **`GET /public/config/integrations` behind auth is correct.** The frontend's dead `configIntegrations` query targeted the pre-auth path; the backend deliberately moved it behind auth (routes/api.php **SEC-1**). No backend change — the frontend just shouldn't call it pre-auth (covered in FE-DRIFT-1).

- **No Resource field gap surfaced.** No finding required a backend Resource to emit a field it currently doesn't (e.g. no `architectureId`/`designKit` shape mismatch). `GET /public/profiles/{handle}` and the design-kit surface matched the frontend's expectations in scope.
